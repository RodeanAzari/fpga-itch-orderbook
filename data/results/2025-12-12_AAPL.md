## Interpretation

This day is about 3 times the size of day 1 (923,744,247 messages; AAPL 3,542,448). The parser
found no malformed messages, unknown refs, duplicates or over-reductions. The largest order
ref is 1,017,886,181, which fits in 32 bits, so `ref_overflow` stays 0. The window base is
27,801 ticks ($278.01).

**Peak live orders: 54,981, about twice day 1's 27,814.** That is 84 % of the
65,536-entry table chosen in ADR 0001. The accepted shape (2 × 8,192 × 4) overflows:
`bounded_check` counts 14,717 dropped inserts, so the later messages for those orders become
1,340,478 `unknown_ref`, and the book is stale from message 56,226 (pre-market) to the end of
the day. `sizing` reports 31,044 overflow inserts for the same shape because it keeps
overflowed orders in a stash, so they keep taking slots. The stale flag covered every wrong
BBO: `unflagged_wrong` is 0, so capacity failed but the book was never silently wrong.

With the same 65,536 entries arranged as 2 × 4,096 × 8, the table still overflows 529 times.
Arranged as **2 × 2,048 × 16, it has 0 overflows on both days.** On that shape, each day's
`bbo_updates` equals its stats run's `bbo_events` (916,429 and 831,842). `price_oow` equals the
independent `adds_out_of_window` (69,799 and 16,099). `bbo_oow` is 3 and 4. Neither book goes
stale. On the overflowing shapes `price_oow` is lower because an out-of-window add that
overflows is never counted. These results are why the table moves to 16 ways (ADR 0010).
Headroom on this day is thin: 84 % load at the peak.
